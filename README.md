# whatsapp-drive-sync

A shared link: whoever opens it links their own WhatsApp for a moment, picks which groups to pull from, and their recent group photos get uploaded straight into one shared Google Drive folder — dated by day.

## איך זה עובד

זה דף ווב אחד, המוגבל למשתמשים שהוגדרו מראש באמצעות שם משתמש וסיסמה. כל מי שנכנס אליו:

1. בוחר איך לקשר את הוואטסאפ שלו: **סריקת QR** (אם יש לו מכשיר נוסף, כמו מחשב + טלפון) או **קוד להזנה ידנית** (אם הוא נכנס מאותו טלפון עצמו, שם אי אפשר לסרוק קוד המוצג על אותו מסך) — וואטסאפ → הגדרות → מכשירים מקושרים → קישור מכשיר → "קישור באמצעות מספר טלפון במקום זאת".
2. ברגע שהתחבר, רואה את רשימת הקבוצות **שהוא עצמו חבר בהן**, ממוינות לפי הפעילות האחרונה (בדיוק כמו רשימת הצ'אטים בוואטסאפ עצמו), עם חיפוש לפי שם ודפדוף (לא רשימה ארוכה אחת) — ובוחר אילו לכלול (עם זיכרון של הבחירה האחרונה בדפדפן שלו, כדי לא לבחור מחדש כל פעם).
3. לוחץ "העלה לדרייב" — המערכת שולפת מההיסטוריה הקרובה (מהטלפון שלו, שכבר קיבל את ההודעות כרגיל) את התמונות מהקבוצות שנבחרו, ומעלה אותן.
4. אחרי ההעלאה אפשר לנסות שוב תמונות שנכשלו או לסנכרן קבוצות נוספות. לסיום לוחצים **סיים והתנתק**; חיבור שלא נעשה בו שימוש נסגר לאחר 20 דקות.

כל התמונות (מכל מי שמסנכרן, מכל קבוצה) עולות לאותה **תיקיית דרייב אחת קבועה** שהוגדרה מראש (למשל תיקיית בית הספר), לתת-תיקייה לפי **תאריך היום** — אם כבר יש תיקייה כזו מסנכרון קודם באותו יום, התמונות מצטרפות אליה. שם כל קובץ הוא **שם השולח** (+ שעה קטנה, רק כדי שתמונות מאותה מורה לא ידרסו זו את זו).

כדי שתמונה לא תועלה פעמיים אם שני אנשים שונים מסנכרנים את אותה קבוצה, המערכת זוכרת (בצד השרת, לא תלוי במשתמש) את מזהי ההודעות שהועלו בהצלחה, ובודקת גם סימון שנשמר על הקובץ בדרייב. תמונה שנכשלה נשארת זמינה לניסיון חוזר.

**חשוב להבין:** מכיוון שכל אחד מקשר את הוואטסאפ _שלו_, מי שרוצה לסנכרן קבוצה מסוימת חייב להיות בעצמו חבר בקבוצה הזו בוואטסאפ.

## התקנה

### 1. דרישות

- מותקן Node.js (גרסה 18 ומעלה) על המכונה/שרת שעליו זה ירוץ.

### 2. התקנת חבילות

```bash
npm ci
```

### 3. הכנת גישה לגוגל דרייב

**חשוב:** חשבון שירות (Service Account) לבדו **לא מספיק** — לחשבון שירות אין מקום אחסון משלו, אז הוא לא יכול ליצור קבצים בדרייב רגיל (לא-Workspace), גם אם שיתפת אותו כ-Editor. הפתרון: האפליקציה מתחברת **כחשבון הגוגל האמיתי של בית הספר** (בדיוק כמו שאתה נכנס בדפדפן), כדי שהקבצים באמת ישתייכו לחשבון שלכם.

1. היכנס ל-[Google Cloud Console](https://console.cloud.google.com/) וצור פרויקט חדש (או השתמש בקיים) — מומלץ עם חשבון הגוגל של בית הספר.
2. הפעל (Enable) את **Google Drive API** עבור הפרויקט.
3. תחת **APIs & Services → OAuth consent screen**: בחר **External**, מלא שם אפליקציה כלשהו ואימייל תמיכה (המייל שלך), שמור. תחת **Test users** הוסף את כתובת חשבון הגוגל של בית הספר (זה שבו נעשה שימוש בפועל) — כי האפליקציה לא "מאומתת" רשמית ורק משתמשי-בדיקה יכולים להתחבר אליה, וזה מספיק בשבילנו.
4. תחת **APIs & Services → Credentials → Create Credentials → OAuth client ID**: סוג = **Web application**. תחת **Authorized redirect URIs** הוסף את הכתובת של האתר שלך + `/admin/google-auth/callback` (למשל `https://whatsapp-drive-sync-zqxx.onrender.com/admin/google-auth/callback`). שמור, ותקבל **Client ID** ו-**Client Secret**.
5. בדרייב של בית הספר (מחוברים עם החשבון הזה!), צור את תיקיית היעד הקבועה (למשל "תמונות מוואטסאפ"). קח את ה-ID שלה מתוך הכתובת בדפדפן (החלק שאחרי `folders/`).

### 4. הגדרת משתני סביבה

```bash
cp .env.example .env
```

ואז ערוך את `.env` (ראה גם הסברים בתוך `.env.example`):

```
GOOGLE_OAUTH_CLIENT_ID=<מה-Credentials>
GOOGLE_OAUTH_CLIENT_SECRET=<מה-Credentials>
GOOGLE_OAUTH_REDIRECT_URI=<אותה כתובת /admin/google-auth/callback שהגדרת>
GOOGLE_DRIVE_PARENT_FOLDER_ID=<ה-ID של תיקיית היעד>
```

**לאחר ההגדרה וההרצה (מקומית או בענן), יש שלב חד-פעמי אחד נוסף:** גלוש בדפדפן, כשאתה מחובר לחשבון הגוגל של בית הספר, אל `<הכתובת שלך>/admin/google-auth/start`, אשר גישה. השרת ישמור את ה־refresh token בקובץ מוגן תחת `DATA_DIR` בלי להציג אותו בדף. אפשר גם לשמר את המשתנה הקיים `GOOGLE_OAUTH_REFRESH_TOKEN` ב־Render; אין צורך להנפיק טוקן חדש אם החיבור הקיים תקין. הרשאת Google עלולה לפוג או להתבטל, ובמצב Testing טוקן עשוי לפוג אחרי שבעה ימים.

### 5. הרצה

```bash
npm start
```

ואז פתח בדפדפן:

```
http://localhost:3000
```

## הפצה לכמה אנשים (הלינק המשותף)

כדי שכל האנשים (אתה, עורך העיתון, ועוד 1-2 נוספים) יוכלו להיכנס לאותו לינק ולסנכרן כל אחד מהוואטסאפ שלו, הדף הזה צריך לרוץ על **שרת נגיש דרך האינטרנט**, לא על `localhost` של מחשב אחד. חשוב: GitHub עצמו לא יכול להריץ את זה (הוא רק מאחסן קוד, לא מריץ שרת), וגם לא Supabase Edge Functions (מתאימות רק לתהליכים קצרים מאוד, לא לתהליך שמחזיק חיבור וואטסאפ פתוח בזמן שמישהו סורק QR).

אפשר להשתמש בשירות Render הקיים עם תהליך Node פעיל ואחסון קבוע. אין ליצור שירות חדש לפני שבודקים האם כבר קיימת פריסה. הגדרות OAuth ותיקיית היעד הקיימות נשארות בתוקף אם הן תקינות.

**אחסון קבוע נדרש בפריסה:** השתמשו בדיסק קבוע בשירות Render הקיים והגדירו `DATA_DIR` לנתיב העגינה שלו. דיסק זמני בטייר החינמי אינו מספיק לשמירת מזהי קבצים לפני העלאה או טוקן שהתקבל בשרת. הסימונים שעל תמונות חדשות נשמרים גם בדרייב, אך אינם מחליפים אחסון קבוע למצב של תגובת העלאה שאבדה. אין לשדרג מסלול או ליצור שירות חדש בלי לבדוק מה כבר קיים.

## גרסת התיקונים — הרצה ופריסה

- ממשיכים בענף `fix/reliable-photo-sync-2026-10` וב־PR #1. אין צורך בהקמת פרויקט חדש.
- לפני פריסה יש לבדוק את השירות הקיים ב־[Render Dashboard](https://dashboard.render.com/), את הענף המחובר, כתובת השירות, המשתנים והדיסק. אין להעתיק סודות לצ׳אט או ללוגים.
- פקודת התקנה: `npm ci`. בדיקות: `npm test`. פקודת הרצה: `npm start`. בדיקת בריאות ל־Render: `/healthz`.
- בפריסה הגדירו `NODE_ENV=production`, נתיב מוחלט ב־`DATA_DIR`, ו־`ACCESS_USERS_JSON` כאובייקט JSON שמפתחיו שמות המשתמשים, וכל ערך כולל `password` (לפחות 12 תווים) ו־`admin` בוליאני. רק מנהל יכול לפתוח את מסלולי Google OAuth. את הערכים האמיתיים מזינים באופן מאובטח ב־Render. האתר משתמש בכניסה דרך חלון האימות של הדפדפן, מעל HTTPS בלבד.
- הפעילו **מופע Node יחיד** (ללא cluster או כמה replicas). נעילת התמונות משותפת לכל המשתמשים באותו תהליך; היא אינה נעילה מבוזרת. מעבר לכמה מופעים מחייב מסד נתונים משותף עם נעילה אטומית.
- קובצי מצב וטוקנים נשמרים ב־`DATA_DIR`; נתוני קישור WhatsApp נשמרים תחת `sessions` ונמחקים בסיום. אין להעלות את התיקייה ל־Git. אחרי קריסה ייתכן שתצטרכו להסיר מכשיר מקושר בטלפון; הפעלה מחדש אינה מבטיחה logout מרחוק.
- תהליך הסנכרון מחזיר HTTP 202 ואז מתקדם ברקע. הלקוח בודק סטטוס; אין בקשת HTTP פתוחה לאורך כל הסנכרון. ההורדה וההעלאה נעשות תמונה־תמונה, עם ויתור למתזמן בכל עשר תמונות. מוצגים נמצאו / הועלו / כבר בדרייב / נכשלו / נותרו.
- שגיאת תמונה בודדת אינה עוצרת את האחרות. לחיצה נוספת מנסה תמונות שנכשלו ומדלגת על הצלחות. ההעלאה משתמשת במזהה קובץ שהוקצה ונשמר מראש כדי שניסיון חוזר אחרי timeout לא ייצור עותק נוסף, כל עוד נשמר `DATA_DIR`.
- השם נלקח מ־`pushName` של ההודעה, מאיש הקשר של המשתתף, או מזיהוי משתתף ברור. בתמונה שנשלחה על ידי המשתמש המחובר עצמו אפשר להשתמש בשמו. שם הקובץ כולל זמן וסיומת קצרה הנגזרת ממזהה ההודעה והקבוצה, כדי להבדיל בין תמונות באותה שנייה ובסנכרונים נפרדים. השם המקורי של שולח שאינו מספק שם אינו ניתן להבטחה.
- הבחירות נשמרות בדפדפן בנפרד לכל חשבון WhatsApp. הן אינן עוברות בין מכשירים. בחירה ישנה ללא זהות משתמש אינה מועברת אוטומטית, כדי לא לשייך קבוצות לאדם אחר.
- הרשימה נטענת בלי להמתין לסיום היסטוריה. מיון הפעילות מתעדכן עם מידע שמגיע, תוך שמירת הסימונים והחיפוש. קבוצות ללא מידע על פעילות מופיעות אחרי קבוצות עם מידע.

### מגבלות שצריך לבדוק לפני שימוש בצוות

Baileys היא ספרייה לא רשמית. WhatsApp מספקת היסטוריה ומדיה לפי זמינותה, ולא בהכרח את כל התמונות בטווח שנבחר. תמונות נוספות שהגיעו אחרי תחילת משימה ייכללו רק בסנכרון הבא. הודעות ומדיה שלא הגיעו מהטלפון אינן ניתנות לשחזור על ידי בחירת תקופה גדולה יותר.

סימוני הדרייב חלים על תמונות שהועלו בגרסה הזו. הצלחות מהגרסה הקודמת נשמרות אם `uploaded-images.json` הקיים נשמר. אם המעקב הישן אבד, אין דרך בטוחה לזהות את כל התמונות הישנות רק לפי שם קובץ. החלפת לקוח OAuth, מחיקת הסימונים או מחיקת מצב הדיסק מחייבות בדיקה מחדש של מניעת כפילויות.

המשימה עצמה נמצאת בזיכרון. אחרי אתחול צריך להתחבר מחדש ולסנכרן שוב; הצלחות שמורות לא אמורות לעלות שוב, אבל יכולת השלמת תמונה שלא הועלתה תלויה בכך ש־WhatsApp תספק אותה מחדש.

### בדיקת משתמש אמיתית — עדיין נדרשת

1. פתחו את כתובת שירות Render הקיים ב־HTTPS והיכנסו כמשתמש מורשה. ודאו שמשתמש רגיל אינו יכול להגיע למסלולי OAuth.
2. ודאו גישה לתיקיית הדרייב עם חשבון בית הספר, בלי להנפיק הרשאות חדשות אם הקיימות תקינות.
3. קשרו WhatsApp ב־QR וגם בקוד מהטלפון. בדקו שהקבוצות מוצגות מהר ושאין הבטחה להיסטוריה שטרם התקבלה.
4. שלחו שתי תמונות באותה שנייה משולח אחר, ובדקו ששמו מופיע בשני קבצים נפרדים בתיקיית התאריך. בדקו גם שולח ללא שם ותמונה שנשלחה מהחשבון המחובר עצמו.
5. בדקו יום, שלושה ימים, שבוע, שבועיים וחודש, ביחס לתמונות שהתקבלו בפועל.
6. נתקו את הרשת או גרמו לכשל מבוקר. בדקו התקדמות, ניסיון חוזר ללא אובדן תמונות וללא העלאת הצלחות מחדש.
7. סנכרנו אותה קבוצה משני משתמשים במקביל. בדקו שנוצר רק עותק אחד לכל הודעה.
8. אתחלו את השירות עם הדיסק הקבוע ובדקו שסנכרון חוזר מדלג על הצלחות.
9. סיימו באמצעות כפתור הניתוק ובדקו בטלפון שהמכשיר הוסר. אם אין אישור, הסירו אותו ידנית.

הבדיקות האוטומטיות מדמות WhatsApp ו־Drive ובודקות כשלים, מניעת כפילויות במופע אחד, שמות, טעינת קבוצות והרשאות HTTP. הן אינן מאמתות גישה לשירותים האמיתיים או התנהגות בטלפון.
